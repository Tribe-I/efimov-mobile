# AGENTS.md — efimov-mobile

Правила для AI-агентов. Человеку тоже полезно: это контракт проекта.

## Назначение

«Командометр» в мобильном приложении: перенос лендинга
[Tribe-I/efimov-komandometr](https://github.com/Tribe-I/efimov-komandometr) на
React Native + Expo (задание 10). Опрос самооценки процессов управления
командой: 13 вопросов, шкала 0–10, пять уровней. Весь подсчёт — на устройстве,
сетевых запросов нет. Только базовые компоненты React Native (View, Text,
Image, ScrollView, Pressable); новые библиотеки — только с согласия владельца.

## Команды

Node.js ставится через nvm (`nvm install --lts`). Вместо `npx` можно `npm exec`.

| Задача | Команда (из корня репозитория) |
| --- | --- |
| Установить зависимости | `npm install` |
| Запустить dev-сервер (Expo Go) | `npm start` |
| Проверка типов | `npx tsc --noEmit` |
| Диагностика проекта Expo | `npx expo-doctor` |

## Expo SDK 58 — не доверяйте тренировочным данным

Expo меняется каждый релиз. Перед кодом, который трогает API Expo/React
Native: проверьте мажорную версию `expo` в `package.json` и читайте
версионные доки <https://docs.expo.dev/versions/v58.0.0/> или индекс
<https://docs.expo.dev/llms.txt>. Версии пакетов ставить через
`npx expo install <package>`.

## Порядок изменений

1. Ветка от свежей `main`: `<логин>/<суть>`, одна тема — один PR.
2. Перед пушем: `npx tsc --noEmit` и ручная проверка в Expo Go (опрос
   считает, сброс работает).
3. PR в `main`: что изменено, как проверить. Прямых коммитов в `main` нет.

## Сборки

- Локальный просмотр — Expo Go: `npm start`, QR-код в терминале.
- Релизные сборки делаются через GitHub Actions (workflow в `.github/workflows/`,
  запуск вручную через `workflow_dispatch`). Токены — только в GitHub Secrets
  (например `EXPO_TOKEN`), в коде — лишь их имена.
- Хеш коммита сборки попадает в приложение через переменную окружения
  `EXPO_PUBLIC_COMMIT`; в код руками не пишется. Локально, без переменной,
  экран «О приложении» показывает `dev`.

## Границы

- Никаких секретов: пароли, ключи, токены, `.env`, cookies и персональные
  данные в репозиторий не кладём.
- Без WebView и показа старой веб-страницы внутри приложения; без Flutter,
  Capacitor и нативного кода вне конфигурации Expo.
- Каталоги `ios/` и `android/` не создавать и не править руками
  (Continuous Native Generation): нативное поведение — через `app.json`
  и config plugins.
